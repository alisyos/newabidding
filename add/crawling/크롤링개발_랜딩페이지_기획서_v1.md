**v1.0 / 2026-09-01**

| 항목 | 내용 |
|---|---|
| 전환 목표 | 무료 상담·견적 폼 제출 |
| 주 타겟 | 에이전시·대행사 / 이커머스·유통 셀러 / 중소기업 실무자 |

## 01. 전략 전제 — 이 페이지가 이기는 방식

크롤링 개발은 이미 크몽·위시켓 같은 오픈마켓에 공급이 넘칩니다. 가격으로 싸우면 5만 원짜리 프리랜서 견적과 비교당하고, 기술력으로만 말하면 구매자(비개발 실무자)가 판단할 수 없습니다. 따라서 이 페이지는 **"싸게 만들어드립니다"가 아니라 "멈추지 않게 책임집니다"** 를 판매합니다.

### 구매자가 실제로 두려워하는 3가지

| | 두려움 | 내용 |
|---|---|---|
| Fear 01 | **만들다 막힐 것 같다** | 로그인·동적 렌더링·IP 차단·캡차. 견적을 받아도 "그래서 되는 건가?"가 해소되지 않습니다. |
| Fear 02 | **두 달 뒤 멈출 것 같다** | 사이트 구조가 바뀌면 크롤러는 죽습니다. 개발자는 이미 떠났고 유지보수 견적을 다시 받아야 합니다. |
| Fear 03 | **법적으로 괜찮은가** | 대법원 판결과 부정경쟁방지법 이슈를 어렴풋이 들었지만, 어디까지가 선인지 아무도 알려주지 않습니다. |

### 포지셔닝 문장

> 크롤러를 **만들어 주는** 곳은 많습니다. 우리는 **계속 돌게 하는** 곳입니다.
> — 개발 · 차단 대응 · 구조 변경 대응 · 법적 검토를 한 팀이 책임집니다.

이 중 **Fear 03(법적 안전성)** 은 국내 경쟁사 랜딩페이지에서 거의 다루지 않는 영역입니다. 별도 섹션으로 정면 배치하면 단가 방어와 신뢰 확보를 동시에 얻습니다. 이것이 이 페이지의 가장 큰 차별화 지점입니다.

## 02. 타겟 3종 — 같은 페이지, 다른 진입점

세 타겟은 페인포인트가 달라 하나의 헤드라인으로 묶기 어렵습니다. 히어로는 공통 메시지로 두되, **섹션 S3(용도별 카드)에서 각자 자기 얼굴을 찾게** 하는 구조로 설계합니다. 광고 소재는 타겟별로 분리하고 랜딩은 하나로 운용합니다.

### Target A — 에이전시 · 대행사

- **상황** — 클라이언트 리포팅용 경쟁사·순위·리뷰 데이터를 매달 인턴이 수기로 정리
- **진짜 문제** — 인건비보다 *납기 압박*. 리포트 마감일에 데이터가 없으면 계약이 흔들림
- **후킹 포인트** — "매달 반복되는 수집 작업을 자동 리포트로." 다건 계약·리셀 가능성이 높은 최우선 타겟

### Target B — 이커머스 · 유통 셀러

- **상황** — 경쟁 상품 가격·품절·리뷰를 하루에도 몇 번씩 눈으로 확인
- **진짜 문제** — 늦게 알면 *매출이 빠짐*. 가격 변동 대응이 시간 싸움
- **후킹 포인트** — "경쟁사 가격이 바뀌면 10분 안에 알림." ROI를 금액으로 계산해 보여주기 가장 쉬운 타겟

### Target C — 중소기업 실무자

- **상황** — 입찰공고·채용공고·업계 뉴스·고객사 동향을 매일 아침 여러 사이트 돌며 취합
- **진짜 문제** — *본인 시간*. 사내에 요청할 개발 리소스가 없고 IT 예산 승인 절차가 부담
- **후킹 포인트** — "출근하면 엑셀이 도착해 있습니다." 소액 진입 → 확장 구조가 유효

## 03. 페이지 구조 — 12섹션 스크롤 설계

번호는 스크롤 순서이자 **설득 순서**입니다.
공감(S3) → 해결(S4·S5) → 능력 증명(S6·S7) → 안심(S8·S9) → 가격(S10) → 잔여 반론 제거(S11) → 전환(S12)

| ID | 섹션 | 구성 |
|---|---|---|
| **S1** ★ | 히어로 + 1차 CTA | 헤드라인 · 서브카피 · 신뢰 배지 3종 · [무료 견적 받기] 버튼 · 우측 결과물 시각화(엑셀 화면) |
| S2 | 신뢰 바 | 누적 프로젝트 수 · 운영 중 크롤러 수 · 평균 가동률 · 고객사 로고 6~8개 |
| S3 | 문제 공감 "이런 상황이신가요" | 타겟 3종 페인포인트 카드. 각 카드가 곧 광고 소재별 착지점 역할 |
| S4 | 수집 가능 대상 | 쇼핑몰 · 포털/검색 · 공공데이터 · 부동산 · 채용 · SNS · 회원제 사이트 등 유형 그리드 |
| S5 | 결과물 형태 | 엑셀/CSV · DB 적재 · API · 슬랙·메일 알림 · 대시보드. 실제 산출물 스크린샷 필수 |
| S6 | 기술 대응력 "이런 것도 됩니다" | 로그인/2FA · JS 동적 렌더링 · IP 차단 · 캡차 · 대용량 분산. 난이도를 인정하며 해결책 제시 |
| S7 | 진행 프로세스 5단계 | 상담 → 사전 기술검토(무료) → 견적 확정 → 개발·검수 → 운영/모니터링. 각 단계 소요일 명시 |
| S8 | 도입 사례 3건 | Before/After + 수치 결과. 타겟 3종에 1:1 대응하도록 배치 |
| S9 | **법적 안전성 ★차별화** | 사전 리스크 체크 항목 · 판례 기준 · 계약서 명문화. 경쟁사가 비워둔 자리 |
| **S10** ★ | 요금 3패키지 + 2차 CTA | 라이트 / 스탠다드 / 운영형(월). 구간 표기 + "정확한 견적은 무료 상담" |
| S11 | FAQ 7문항 | 가격·기간·법적·유지보수·차단·소스코드 소유권·환불. 남은 반론 제거 |
| **S12** ★ | 최종 CTA — 문의 폼 | 4필드 폼 · 응답 시간 약속 · 카카오 상담 보조 버튼 · 푸터(사업자정보·개인정보처리방침) |

> **CTA 배치 원칙**
> 주 CTA는 **S1 · S10 · S12** 3곳. 추가로 모바일에서는 스크롤 30% 이후 하단 고정 바를 노출합니다. 중간 섹션에 CTA를 흩뿌리면 "설득 전 요구"가 되어 전환율이 떨어집니다.

## 04. 섹션별 상세 스펙 & 카피 초안

### S1 — 히어로

**목적** — 3초 안에 "내 문제를 해결해주는 곳"임을 인지시키고 1차 전환 시도

**카피 A안**
> ### 사람이 매일 하던 데이터 수집,<br>내일부터 프로그램이 합니다.
> 필요한 사이트, 필요한 항목만 골라 맞춤 제작합니다. 엑셀·DB·알림까지 원하는 형태로 받아보세요.

**카피 B안**
> ### "이 사이트에서 이 데이터, 매일 뽑아주세요."
> 그 한 문장이면 됩니다. 기술 검토부터 운영까지 저희가 맡습니다.

**추천** — A안을 기본으로 하고 B안을 A/B 테스트. A안은 **대체되는 노동**을, B안은 **진입 장벽 제거**를 팝니다. 검색광고 유입은 A안, 리타게팅은 B안이 유리할 가능성이 높습니다.

**구성요소**

- 신뢰 배지 3종 — "무료 사전 기술검토" / "법적 리스크 사전 진단" / "운영 중 장애 대응 포함"
- 주 버튼 **[1분 만에 무료 견적 받기]** — "문의하기"보다 소요시간·무료를 명시
- 보조 링크 [실제 사례 먼저 보기] → S8 앵커
- 우측 비주얼 — 수집 결과 엑셀 시트 화면. 추상적 일러스트 금지, 실제 산출물이 가장 강력한 증거

### S6 — 기술 대응력

**목적** — "우리 사이트는 어려울 텐데"라는 자기 검열로 인한 이탈을 막습니다. 이탈 사유 1위로 추정되는 지점

**헤드라인**
> ### 막힐 것 같아서 포기하셨다면, 그게 저희가 하는 일입니다.

**구성** — 난이도를 인정한 뒤 해결책을 제시하는 2단 카드 5종

1. 로그인 · 2단계 인증
2. JS 동적 렌더링 · 무한 스크롤
3. IP 차단 · 요청 제한
4. 캡차
5. 수십만 건 대용량 · 정기 스케줄링

**카피 예** — "로그인해야 보이는 데이터라서요" → **세션 유지·토큰 갱신 방식으로 로그인 이후 화면까지 수집합니다.**

> ⚠️ **주의** — 캡차 우회는 표현 수위 관리 필요. "우회"보다 **"정상 접근 범위 내 처리 방식 협의"** 로 표기해 법적·평판 리스크를 줄입니다.

### S7 — 진행 프로세스

**목적** — "얼마나 걸리나" "뭘 준비해야 하나"에 답하고, **무료 사전 기술검토**를 리드 확보 장치로 노출

| 단계 | 내용 | 소요 |
|---|---|---|
| 1. 상담 신청 | 수집 대상 URL·항목만 알려주시면 끝 | 당일 |
| 2. 무료 사전 기술검토 | 실제 접속해 수집 가능 여부·난이도 확인 후 리포트 회신 | 1~2영업일 |
| 3. 견적·범위 확정 | 항목/주기/산출물 확정, 계약 | 1~3영업일 |
| 4. 개발 & 검수 | 샘플 데이터 먼저 전달 후 확인받고 완성 | 5~15영업일 |
| 5. 운영 & 대응 | 정상 동작 모니터링, 사이트 구조 변경 시 수정 | 계약 기간 |

> **핵심** — **2단계가 이 페이지의 진짜 무기**입니다. 무료 기술검토는 리드에게 "손해 볼 게 없다"는 명분을 주고, 영업팀에는 상담 재접촉 사유를 만들어 줍니다. 히어로 배지에도 반드시 반복 노출하세요.

### S9 — 법적 안전성 ★

**목적** — 구매 결정권자(대표·팀장)의 마지막 반대 사유를 제거하고, 동시에 저가 프리랜서 견적과의 차별점을 만듭니다

**헤드라인**
> ### "이거 해도 되는 건가요?" 그 질문부터 같이 검토합니다.

**내용**

- **착수 전 체크 4항목** — 이용약관·robots.txt 확인 / 로그인·유료 회원 데이터 여부 / 수집량과 서버 부하 수준 / 개인정보 포함 여부
- **판례 기준 요약** — 대법원은 **① 접근권한 제한 여부, ② 데이터베이스 상당 부분의 반복·체계적 복제 여부, ③ 현실적 업무 장애 발생 여부**를 나눠 판단합니다. 공개 정보의 소량 수집과 회원 계정을 통한 대량 수집은 완전히 다른 사안입니다.
- **운영 원칙** — 요청 간격 제어로 대상 서버 부하 최소화, 수집 범위 계약서 명문화

> ⚠️ **필수** — 면책 문구를 반드시 병기하세요.
> **"법률 자문이 아니며, 최종 판단은 의뢰인 책임입니다. 리스크가 높다고 판단되면 프로젝트를 수임하지 않습니다."**
> 수임 거절 원칙을 밝히는 것이 오히려 신뢰를 만듭니다.

### S12 — 최종 CTA · 문의 폼

**설계 원칙** — 필드는 **4개까지**. 그리고 이 4개가 그대로 견적 산정 인풋이 되도록 설계합니다 — 리드 수집과 사전 견적을 한 번에 처리

| # | 필드 | 유형 |
|---|---|---|
| ① | 수집하고 싶은 사이트 주소 | 필수 · 텍스트 ("여러 개면 줄바꿈") |
| ② | 필요한 데이터 항목 | 필수 · 텍스트 (placeholder "상품명, 가격, 리뷰 수") |
| ③ | 수집 주기 | 선택 · 라디오 (1회 / 매일 / 실시간 / 미정) |
| ④ | 연락처 | 필수 · 이메일 또는 휴대폰 택1 |

**버튼** — **[무료 기술검토 신청]**
**마이크로카피** — "영업일 기준 1일 내 수집 가능 여부를 회신드립니다. 상담 후 진행하지 않으셔도 비용은 없습니다."

**제출 후** — 감사 페이지 대신 **인라인 확인 메시지 + 자동 회신 메일**. 회신 메일에 사례집 PDF를 첨부해 2차 접촉 명분을 확보합니다.

## 05. 가격 노출 전략 — 권장안과 근거

미정으로 남겨두신 항목입니다. 조사 결과와 타겟 구성을 근거로 **"구간형 3패키지 노출 + 정확한 견적은 상담"** 을 권장합니다.

### 시장 가격대 (조사 기준)

| 구분 | 가격대 | 포함 범위 |
|---|---|---|
| 기초 (단일 페이지) | 5만 ~ 30만원 | 정적 페이지 텍스트 수집, CSV/엑셀 저장 |
| 중급 | 100만 ~ 300만원 | 로그인 처리, 필터, 이미지·파일 다운로드, DB 연동 |
| 고급 | 300만 ~ 500만원+ | 클라우드 스케줄링, 대용량 분산, 차단 대응, 유지보수 |
| 구독형 운영 대행 | 월 300만 ~ 1,200만원 | 개발+운영+유지보수 올인클루시브, 전담 매니저 |

### 권장 패키지 구성

| 패키지 | 표기 가격 | 대상 | 역할 |
|---|---|---|---|
| **라이트**<br>1회성 수집 | 50만원 ~ | 중소기업 실무자 | 진입 장벽 해제용 앵커. 마진보다 **리드 유입**이 목적 |
| **스탠다드**<br>정기 자동 수집 | 200만원 ~ | 이커머스 셀러 | 주력 상품. **"가장 많이 선택"** 배지로 시선 고정 |
| **운영형**<br>개발 + 월 운영 | 월 50만원 ~ | 에이전시·대행사 | LTV 최대. 구독 매출 전환의 핵심 |

> **노출을 권장하는 이유**
> 세 타겟 모두 **예산 승인이 필요한 실무자**입니다. 가격이 없으면 내부 보고서를 쓸 수 없어 문의 자체를 미룹니다. 또 "~부터" 표기는 5만 원 프리랜서를 기대하고 들어온 저품질 리드를 자연스럽게 걸러내, 영업팀의 상담 1건당 생산성을 높입니다.

> ⚠️ **단가 방어 장치 — 함께 넣어야 함**
> 가격 표 바로 아래에 **"가격은 수집 대상 사이트의 구조와 난이도에 따라 달라집니다. 정확한 금액은 무료 기술검토 후 안내드립니다"** 를 반드시 병기하세요. 이 한 줄이 없으면 표기 금액이 상한선으로 인식되어 협상 여지가 사라집니다.

**대안** — 초기 2~4주는 가격 비노출로 운영해 문의량 기준선을 만든 뒤, 위 구성으로 전환해 *문의 수*가 아니라 *유효 상담 수*가 늘었는지로 판정하는 방법도 유효합니다. 최종 결정 전 실제 원가 구조 확인이 필요하니, 위 금액은 초안으로 봐 주세요.

## 06. FAQ 7문항 — 남은 반론 제거

순서는 *실제 문의 빈도순*이 아니라 **구매 저항 크기순**으로 배치합니다.

1. **비용이 얼마나 드나요?** → 난이도 요인(로그인 여부·동적 페이지·수집량)을 설명하고 패키지 앵커로 연결
2. **기간은 얼마나 걸리나요?** → 단순 5영업일 / 일반 2주 / 복합 3~4주
3. **법적으로 문제 없나요?** → S9 요약 + 사전 검토 원칙
4. **사이트가 바뀌면 어떻게 되나요?** → 운영형 계약 시 무상 대응 범위 명시. *가장 중요한 업셀 문항*
5. **차단당하면요?** → 요청 간격 제어·접근 방식 조정으로 대응, 불가 판정 시 사전 고지 원칙
6. **소스코드는 저희가 갖나요?** → 인도 조건 명시. *에이전시 타겟이 반드시 묻는 문항*
7. **중간에 안 되면 환불되나요?** → 사전 기술검토에서 불가 판정 시 착수하지 않으므로 상황 자체가 발생하지 않음 — 이 구조 자체가 세일즈 포인트

## 07. 전환 측정 설계

| 이벤트 | 트리거 | 용도 |
|---|---|---|
| `hero_cta_click` | S1 주 버튼 클릭 | 헤드라인 A/B 판정 |
| `scroll_50` / `scroll_75` | 스크롤 깊이 | 이탈 구간 진단 — S6·S9 앞에서 끊기면 카피 재작업 |
| `pricing_view` | S10 노출 3초 | 가격 노출 후 이탈률 측정 (노출 전략 판정 근거) |
| `form_start` | 첫 필드 입력 | 폼 시작 대비 완료율 = 필드 부담도 |
| `form_submit` | 제출 성공 | **주 전환 지표** |
| `kakao_click` | 카카오 상담 클릭 | 폼 기피층 규모 파악 |

### 판정 기준

- **1차 목표** — 방문 대비 폼 제출 **2~3%**. B2B 서비스 랜딩의 통상 범위
- **폼 시작 → 완료율 70% 미만**이면 필드를 3개로 줄이거나 2단계로 분할
- **scroll_75 도달률 40% 미만**이면 S3~S6이 길다는 신호 — 카드 수 축소
- 유효 상담(견적 진행 의사 있음) 비율을 함께 기록해 가격 노출 전후를 비교

## 08. 제작 전 준비물 체크리스트

기획서가 있어도 아래가 없으면 페이지는 빈 껍데기가 됩니다. **사례 3건과 산출물 스크린샷이 가장 중요**하며, 이것만으로도 전환율이 크게 갈립니다.

- [ ] **도입 사례 3건** — 타겟 3종에 각 1건씩, 수치 결과 포함 <br>*담당: 영업 / 고객사 공개 동의 필요*
- [ ] **수집 결과 산출물 스크린샷** — 엑셀 시트, 알림 화면, 대시보드 <br>*담당: 개발 / 민감정보 마스킹 필수*
- [ ] **고객사 로고 6~8개** 또는 대체 지표(누적 건수·가동률) <br>*담당: 영업 / 로고 사용 동의 확인*
- [ ] **패키지 3종 원가·마진 검증** <br>*담당: 영업 + 개발 합의*
- [ ] **무상 유지보수 범위 정의** — "사이트 구조 변경 대응"의 경계 <br>*담당: 개발 / 계약서 반영*
- [ ] **수임 거절 기준 문서화** — 어떤 요청을 받지 않을 것인가 <br>*담당: 영업 + 법무 검토*
- [ ] **문의 유입 → 담당자 알림 경로** <br>*담당: 개발 / 슬랙·메일 즉시 알림 권장*
- [ ] **개인정보 수집·이용 동의 문구 및 처리방침** <br>*담당: 법무 / 폼 하단 필수*
