# AI 배너 리사이징 서비스 페이지 기획안

-   문서 버전: v1.0
-   작성 기준: 2026년 9월
-   목적: 사용자가 원본 배너를 업로드하고 AI 이미지 모델을 선택하여
    다양한 광고 규격으로 자동 리사이징·재구성하는 웹 페이지 기획

------------------------------------------------------------------------

## 1. 서비스 개요

### 1.1 서비스 목적

하나의 원본 광고 배너를 업로드하면 사용자가 원하는 광고 규격에 맞게
배너의 주요 요소를 재배치하고, 부족한 이미지 영역을 생성형 AI로
자연스럽게 확장하여 복수의 배너를 생성한다.

사용자는 작업 시 아래 2개 모델 중 하나를 직접 선택할 수 있다.

1.  **Gemini 3.1 Flash Image (Nano Banana 2)**
2.  **GPT-Image-2**

### 1.2 핵심 사용자 흐름

`원본 배너 업로드 → AI 모델 선택 → 출력 사이즈 선택 → 옵션 설정 → AI 리사이징 실행 → 결과 비교/검수 → 다운로드`

### 1.3 핵심 원칙

-   원본의 상품, 인물, 로고, 광고 문구 등 핵심 요소를 최대한 보존한다.
-   단순 Stretch 방식으로 이미지 비율을 변경하지 않는다.
-   목표 비율에 맞춰 레이아웃을 재구성한다.
-   부족한 배경 영역은 선택한 생성형 AI 모델을 이용해 확장한다.
-   로고 및 텍스트는 가능하면 AI가 다시 그리지 않고 원본 요소를
    재사용한다.
-   사용자가 AI 모델별 결과를 직접 선택할 수 있도록 한다.

## 2. 대상 사용자

### 광고 운영자

매체별로 다양한 규격의 광고 배너를 반복 제작해야 하는 사용자.

### 디자이너

기존 디자인을 기반으로 다수의 파생 소재를 빠르게 제작하고 최종 결과만
보정하려는 사용자.

### 광고대행사

하나의 캠페인 소재를 네이버, 구글, 메타, 카카오 등 다양한 광고 규격으로
대량 변환해야 하는 사용자.

## 6. 출력 배너 사이즈 선택

### 6.1 프리셋 선택

사용 빈도가 높은 규격을 사전 등록한다.

예시:

  구분                 사이즈
  ------------- -------------
  정사각형        1080 × 1080
  가로형           1200 × 628
  와이드 배너      1200 × 300
  디스플레이        300 × 250
  세로형            300 × 600
  리더보드           728 × 90
  모바일 배너       320 × 100

실제 운영 시에는 광고 매체별 규격을 관리자에서 추가·수정할 수 있도록
설계한다.

### 6.2 매체별 선택 확장

향후 다음과 같은 구조로 확장할 수 있다.

``` text
[네이버]
☑ 1200×300
☐ 1200×600

[Google]
☑ 300×250
☑ 728×90
☐ 300×600

[Meta]
☐ 1080×1080
☐ 1080×1350
☐ 1080×1920
```

### 6.3 직접 입력

사용자가 직접 Width / Height를 입력할 수 있도록 한다.

``` text
가로 [ 1200 ] px
세로 [  300 ] px

[사이즈 추가]
```

복수 규격을 한 번에 등록할 수 있도록 한다.

## 10. 생성형 AI 적용 범위

AI 모델이 모든 요소를 새로 생성하도록 하지 않는 것을 권장한다.

### AI 적용 권장

-   배경 확장
-   배경 오브젝트 생성
-   잘린 배경 연결
-   여백 생성
-   비율 변경에 따른 자연스러운 이미지 보완
-   필요한 경우 상품/인물 주변 이미지 연결

### 원본 유지 권장

-   브랜드 로고
-   가격
-   할인율
-   상품명
-   광고 문구
-   CTA 텍스트
-   법적 고지 문구

특히 광고 문구와 브랜드 로고를 AI가 새로 생성할 경우 오탈자 또는 브랜드
훼손 가능성이 있으므로 **원본 레이어를 유지하거나 별도 추출 후
재합성하는 구조**를 권장한다.

## 12. 핵심 기능: 다른 모델로 재생성

사용자가 결과가 만족스럽지 않을 경우 동일 조건을 유지하면서 다른 모델로
재생성할 수 있도록 한다.

예:

``` text
현재 결과
Nano Banana 2

[동일 모델로 재생성]

또는

[GPT-Image-2로 다시 생성]
```

이 기능은 두 모델을 제공하는 서비스의 차별화 요소가 될 수 있다.

향후에는 동일 배너를 두 모델로 동시에 생성하여 A/B 비교하는 기능으로
확장할 수 있다.

## 13. 결과 비교 기능

향후 권장 기능으로 **AI 모델 비교 모드**를 제공한다.

``` text
             Nano Banana 2        GPT-Image-2

1200×300       [IMAGE]              [IMAGE]

               ○ 선택               ○ 선택
```

사용자가 더 좋은 결과를 직접 선택하고 다운로드한다.

이 데이터를 저장하면 향후 서비스 자체의 모델 추천 로직에도 활용할 수
있다.

예:

-   특정 비율에서 어떤 모델의 선택률이 높은지
-   상품 광고에서 어떤 모델이 선호되는지
-   인물 광고에서 어떤 모델이 선호되는지
-   재생성 비율
-   사용자 최종 선택 모델

## 14. 자동 검수

생성 완료 후 시스템에서 기본 검수를 수행한다.

### 검수 항목

-   주요 상품 잘림 여부
-   인물 얼굴 잘림 여부
-   로고 영역 훼손 여부
-   텍스트 영역 훼손 여부
-   원본 대비 주요 객체 유사성
-   출력 사이즈 일치 여부

예:

`⚠ 원본 상품 영역이 일부 변경되었을 가능성이 있습니다.`

사용자는 해당 이미지만 재생성할 수 있다.

## 21. PoC 권장 시나리오

초기 검증에서는 약 30\~50개의 서로 다른 광고 소재를 준비한다.

소재 유형은 다음과 같이 다양하게 구성한다.

-   상품 중심 배너
-   인물 중심 배너
-   텍스트 중심 배너
-   로고 비중이 높은 배너
-   배경이 복잡한 배너
-   정사각형 원본
-   가로형 원본
-   세로형 원본

동일 원본을 두 모델에서 각각 생성하여 비교한다.

### 핵심 테스트 규격

-   1200 × 300
-   728 × 90
-   300 × 250
-   300 × 600
-   1080 × 1080
-   1080 × 1920

특히 `728×90`, `1200×300`, `300×600`처럼 원본과 비율 차이가 큰 규격을
중점적으로 테스트한다.

## 22. 최종 사용자 시나리오

``` text
1. 사용자가 원본 배너를 업로드한다.

2. 시스템이 원본 이미지 크기와 주요 요소를 분석한다.

3. 사용자가 AI 모델을 선택한다.
   - Nano Banana 2
   - GPT-Image-2

4. 원하는 광고 배너 규격을 선택한다.

5. 필요하면 직접 사이즈를 추가한다.

6. 'AI 리사이징 시작'을 클릭한다.

7. 시스템이 주요 객체를 유지하면서 레이아웃을 재구성한다.

8. 선택된 AI 모델이 부족한 이미지 영역을 생성한다.

9. 원본 로고와 텍스트를 재합성한다.

10. 규격별 결과가 생성된다.

11. 사용자가 결과를 확인한다.

12. 만족스럽지 않은 이미지는 재생성하거나 다른 모델로 생성한다.

13. 최종 결과를 개별 또는 ZIP으로 일괄 다운로드한다.
```

## 23. 최종 제안

본 서비스는 단순한 이미지 `Resize Tool`보다는 **AI Creative Adaptation
Tool**의 방향으로 설계하는 것을 권장한다.

핵심 가치는 다음과 같이 정의할 수 있다.

> **원본 광고 소재 1개를 업로드하면 원하는 AI 모델을 선택하여 다양한
> 광고 매체·규격에 맞는 소재를 자동 생성한다.**

초기 MVP에서는 **Gemini 3.1 Flash Image (Nano Banana 2)**와
**GPT-Image-2**를 사용자가 직접 선택하도록 하고, 이후 실제 사용 데이터를
기반으로 `추천 모델 자동 선택` 기능을 추가하는 방향이 적절하다.

장기적으로는 배너 사이즈 변경을 넘어 **매체별 규격 자동 변환 → 레이아웃
최적화 → 광고 문구 최적화 → 소재 Variation 생성 → 성과 기반 추천**까지
확장할 수 있다.
